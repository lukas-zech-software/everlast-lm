## Exact channel and budgets

Objects live at `private-benchmark/v1/<campaign>/<candidate40>/<revision>/<bootUUID>/`: immutable challenge, immutable `approvals/<authorizationUUID>.json`, CAS `inbox.json`, immutable content-addressed allowlisted exports, CAS `exports.json`. Separate immutable discovery pointers use the candidate/revision `discovery/<bootUUID>.json` prefix; at most32boots are listed. A boot is explicitly selected; multiple candidates are not auto-selected. Old boots expire and are not usable.

The separately trusted deployment expires_at is absolute and required; restart/new boot cannot renew the approved storage window. Startup after expiry fails closed. Default per server channel and per operator process: duration<=3600000ms, ticks<=3600, object-port operations<=20000, writes<=1024, write bytes<=128000000, read bytes<=256000000, object<=8000000bytes, object call deadline<=5000ms. Single-attempt SDK disables automatic retries (`autoRetry=false,maxRetries=0`), non-resumable uploads; **put costs save+getMetadata =2GCSRPCs**, stat/read/list each<=1, so conservative physical storage ceiling<=40000GCSRPCs per process, plus ordinary keyless credential exchange. Post-write metadata MD5 binds the returned generation to intended bytes. Generations remain opaque decimal strings, including above2^53. Deadline/abort never permits overlapping in-flight effects or favorable late qualification; a stuck ignored-abort adapter closes the channel. No retries or automatic budget extension. Unchanged operator follow uses one mutable-index metadata request/tick and zero blob bytes; only changed refs are redownloaded, with latest-only per-kind cache <=5objects/40MB. Mutable index/challenge schemas, generation/hash and identity are rechecked; every cached use rechecks retained calibration/expiry.

Private operational setup per signed authorization:2retrieval embeddings,2model generations, <=512outputtokens/model call, <=100000serialized request bytes/model call,2countTokens,2cache creates,2cache deletes, cacheTTL60s, no additional managed creates. SDK attempts1. Cache original streaming memory guard32MB remains; **native serialized cache contents<=10000000bytes before count/create**, actual tokenizer total+18000reserve<=1048576. No truncation. A million-token declared fixture must fit native byte cap and real model minimum/cache availability; local counts do not prove provider capacity. Ordinary small010fixtures may require separately predeclared larger cache source scope; no fake cache success. Timed2500ms/15000ms cohort thresholds are unchanged and separate from setup deadlines<=240000ms. C-02 authorization/revision checks surround source reads and cache creation/deletion/cleanup.

Sanitized transport and operational outcomes retain <=100events each; code/scale retain <=2000rows. Overflow fails closed; it never drops failed attempts to manufacture a pass. Export schemas reject unknown fields, source text, code, stdout, raw provider handles and credentials. Valid computed terminal rows remain in the denominator. A transport failure invalidates readiness. An uncertain delivered remote write cannot be revoked by a missing HTTP/storage acknowledgment: a valid signed approval may already be present. Never blindly retry a failed delivery or substitute a new cohort. ## Acquire and install calibration on the serving boot

Set `BENCHMARK_BRIDGE_CLOCK_BOOTSTRAP=true` in the approved bridge window. Supply `BENCHMARK_BRIDGE_EXECUTION_CONFIG` with exactly `metadata`, `runtime` and `qualification`. Omit `metadata.clock_calibration_sha256` from the frozen metadata. The API validates the candidate, revision, runtime hash, qualification hash and approved notebooks before it opens the clock channel. Leave the clock flag absent for an existing deployment that uses separately measured, retained calibration.

Provision a dedicated serving Ed25519 receipt key through the existing Secret Manager process and independently give its public PEM to the operator. Set `BENCHMARK_BRIDGE_CLOCK_SECRET_ID` to the preexisting same-project secret ID and `BENCHMARK_BRIDGE_CLOCK_SECRET_VERSION` to its numbered version in the non-secret bridge input map. Only the API receives the secret value through `BENCHMARK_BRIDGE_CLOCK_RECEIPT_PRIVATE_KEY`. The secret value stays outside IaC inputs and state. Keep the distinct owner signing key on the operator host and its public key pinned in deployment. The real secret, its regional placement, the API principal's access and the operator's authorized bucket identity need verification and separate deployment approval.

Use a dedicated owner-private output directory for each run. Discover signed boot identities with:

```sh
pnpm benchmark:private clock-discover --bucket BUCKET --identity-file PRIVATE/identity.json --receipt-key-file PRIVATE/serving-public.pem
```

Record the exact selected `instance_boot_id` in the identity file and acquire calibration on the same host that will collect the timing cohort:

```sh
pnpm benchmark:private clock-acquire --bucket BUCKET --identity-file PRIVATE/identity.json --receipt-key-file PRIVATE/serving-public.pem --public-key-file PRIVATE/owner-public.pem --private-key-file PRIVATE/owner-key.pem --directory PRIVATE/output
```

For an isolated local diagnostic use `--local-root` instead of `--bucket`. The server signs its challenge and captured t2/t3 receipt. The CLI measures t1 immediately before the signed request and t4 after verifying the serving signature and exact receipt/request references. It saves `clock-proof.json` before delivering a signed install via CAS. The API recomputes the interval, checks freshness and its own clock continuity, and atomically retains the proof on the same boot. The serving-signed acknowledgment binds the precise install generation and calibration digest. The API opens the ordinary approval coordinator after acknowledgment publication succeeds. The CLI verifies and retains `clock-installed.json` as soon as it sees the serving acknowledgment. It writes canonical `calibration.json` after the corresponding ordinary challenge confirms the handoff. A failed or missing acknowledgment can leave retained proof and committed calibration. Inspect the evidence and serving state before attempting any fresh acquisition. A valid install still requires ordinary scoped operational probe authorization and actual dependency observations.

Clock-only limits are 3,600 ticks at 500ms, 10,000 logical storage operations, 35 writes and 1MiB in each direction, all inside the fixed deployment expiry. Each storage call has an upper bound of 5s. The timed nonce exchange has a 5s total deadline. Conditional writes and pinned reads preserve the exact generation. The signed proof retains actual wall timestamps and monotonic elapsed times within each participating process. The widened interval allows for capture resolution and bounded continuity, and rejects uncertainty over 1,000ms. The server checks its continuity and conservative expiry at install, operational authorization, readiness and publication. The CLI checks continuity throughout acquisition and confirmation.

The calibration has a 60s maximum lifetime and one installation per boot. Live setup, timed submissions and qualified evidence download must all fit the conservative validity window. The local roundtrip exercised a short workload. An independent collector process has a separate `performance.now()` origin, so the retained elapsed times alone do not establish continuity from acquisition into that process. Live 010/012 timing qualification remains UNAVAILABLE until those gaps and actual deployed evidence are resolved.
