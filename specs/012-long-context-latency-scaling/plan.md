## Phase 1 Design (`NFR-PERF-01`, `C-01..C-03`)

1. Reuse migration 0002's existing `chunks` (vector 768, generated `simple` tsvector, cosine HNSW/GIN) and `source_revisions.embedding_model`. Ingestion already persists embeddings with canonical `source_pages`; do not recreate an index generation or invent a `document_chunks` migration. Qualify the deployed embedding model/dimensions and extension version in the benchmark manifest. Preserve applied migrations and existing content.
2. Reuse `RequestScopedContextProvider` and `retrieveScopedChunks`: snapshot verification in transaction, notebook/source/revision predicates on vector and FTS, deterministic RRF 60, current defaults 40 candidates/12 results, transaction-local iterative_scan relaxed_order/ef_search 100, and defense-in-depth membership. Existing FTS builds a bounded OR lexeme query; do not replace it with a supposed existing websearch query. Calibrate ANN against exact scoped distance ranking, then freeze configuration before acceptance. Underfilled/low-recall scoped candidates justify additive exact fallback or tuning; never broaden filters. Keep current defaults until evidence supports a change rather than importing old 64/16 settings as fact.
3. Deterministically classify explicit whole-collection synthesis requests as broad; ambiguous/detail requests retain detailed retrieval. Broad 40-source fixture includes all 40 matching Source Guides and original detail references. Guides are routing aids, cannot replace detailed evidence. Enforce a complete model envelope budget including instructions, eligible history, guide provenance, chunk markers and output reserve. If context cannot fit, return explicit capacity failure or use an already-approved complete-evidence Studio path; never truncate or silently drop a required guide/chunk.
4. Studio computes normalized-source token total independently from guide/decoy tokens. At ≤1,000,000 source tokens use full original text with private context caching only when full envelope fits the qualified model. Configure an approved model envelope large enough for this boundary; if unavailable, fail qualification rather than claim support. Above 1,000,000 process every original chunk starting from current report bounds 4,000 source tokens/8 chunks and extract concurrency 4, further reduced for the actual model envelope; recursively reduce bounded structured findings retaining original references. An oversized individual chunk is subdivided with parent-chunk ID and offsets, never emitted as an over-budget exception. Coverage manifest must match every original chunk and every segment before publication. No unbounded all-findings compose request.
5. Caches include notebook, canonical exact source/revision set, effective authorization fingerprint, language, generation parameters, model/version and content digest. Recheck ACL/revisions before creation, every use/read and publication; invalidate on deletion/replacement/revocation. Same Owner with changed ACL cannot reuse the prior entry. Cache miss/expiry rebuilds from the same authorized original scope; failure cannot substitute a summary-only context. Provider cache creation/usage is enterprise EU only; do not store private content in generic logs.
6. Preserve D13 full-answer buffering/validation; start client monotonic timing immediately before submission dispatch and stop when the client receives the `final` SSE message containing the first non-replayed validated factual answer (current transport buffers the whole answer). There is no raw answer token stream; statuses are retrieving/generating/verifying. A replay cannot serve as a fresh measured generation. Include transport, queue, embedding/retrieval, generation, citation validation and persistence overhead on that path. Instrument stage durations diagnostically without subtracting them. Invalid citation refuses immediately; no valid answer timestamp is manufactured from status, raw model token or refusal.
7. Freeze benchmark manifest/configuration and the fixed 20 warm sample size before collection; this small acceptance fixture is not a statistical assurance of production P95. Use 20 warm sequential needle runs on one Owner notebook; nearest-rank P95=x[ceil(.95×20)]=x[19]. Every run must give 142.8 bar/needle citation, zero 155.0 bar prompt/answer decoy. Missing/failed answer records failure and infinite timing for aggregation; never drop failures. Additional two-Owner/two-notebook 20-run concurrency 2 profile diagnoses expected small-team usage, reports separate results and does not redefine the card's core acceptance. Separate wake cohort and 300-source quota-scale correctness/coverage scenarios are required reports; no invented wake threshold.

## Task-analysis refinements (2026-10-22; `NFR-PERF-01`, `C-02/C-03`, `NFR-SEC-02`, `NFR-EVAL-04`)

Context-cache metadata is process-local to the executing adapter instance; it stores no alternate source corpus and requires no database migration. Every provider cache creation sets an explicit finite expiry (record the configured TTL and provider-confirmed expires_at; reject missing, nonpositive or non-finite values). Revalidate exact scope, current authorization and revisions through C-02 before every use and publication. Invalidation immediately removes local eligibility and attempts idempotent provider deletion; cleanup failure never restores eligibility. On restart, do not discover or reattach orphan handles: treat them as misses and rebuild only from reauthorized original chunks. Provider expiry bounds orphan lifetime; it never grants access or replaces immediate application-side invalidation.

JSON observations encode a missing/failed factual answer with client_first_validated_answer_ms=null, latency_ms=null and an explicit terminal failure/refusal/cancelled status. Derive positive infinity only inside aggregation, never serialize Infinity or NaN. A failed aggregate serializes p95_ms=null with result=FAIL and the retained failure observations; any valid warm failure fails acceptance regardless of rank. Unavailable readiness/sample prerequisites serialize result=UNAVAILABLE separately; neither null nor unavailable means zero latency.
